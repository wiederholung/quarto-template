# 使用说明

新项目已包含中英文写作示例、公共配置、Word 参考文档、CSL、作者扩展，以及示例图片和文献。可以直接开始写作和渲染，无需运行初始化脚本。测试、维护脚本和开发验证文档仅留在模板仓库。

## 开始写作

选择 `template-zh.qmd` 或 `template-en.qmd`，按需要重命名，替换标题、作者、日期、摘要、机构、邮箱和文献。两份示例覆盖相同功能；不需要的示例可以删除。

在项目目录运行（文件重命名后相应修改命令）：

```powershell
quarto render template-zh.qmd --to docx
quarto render template-zh.qmd --to pdf
quarto preview template-zh.qmd --to html
```

输出统一写入 `output/`。HTML、Word 不需要 R/Python；PDF 需要 XeLaTeX、CTeX、KOMA-Script 及相应 LaTeX 宏包。示例代码为静态展示，不执行计算。

## 配置与写作规范

- `_quarto.yml` 统一设置输出目录、IEEE CSL、章节编号、HTML 目录、PDF 页边距和过滤器。
- 单篇 QMD 设置标题、作者、语言、日期、文献文件、HTML 主题、Word 参考文档和 PDF 文档类。
- 中文 PDF 使用 `ctexart`，英文使用 `scrartcl`，两者四边页边距均为 1 英寸（25.4 mm）。标题、字体及段落沿用文档类及 Quarto 的处理。
- 两份示例各自在 `format.html.theme` 中选择 `litera`。HTML 使用原生作者区；分享网页时将同名的 `*_files/` 和 `figures/` 随 HTML 一起复制。Word 和 PDF 使用项目内的 `authors-block` 扩展。
- Word 中的网址、章节与文献引用均可点击，默认显示为黑色。调整 Word 链接颜色时，修改参考文档的“超链接”和“访问过的超链接”字符样式。PDF 的链接颜色由 `format.pdf.colorlinks` 控制。
- 正文标题从 `#` 开始，下一层用 `##`；不写手工编号，不设置层级偏移。
- `number-sections: true` 开启章节编号。交叉引用使用 `@sec-...`、`@fig-...`、`@tbl-...`、`@eq-...`，编号由 Quarto 生成；Word 的 F9 不会重新计算章节数字。
- 参考文献标题写成 `# 参考文献 {.unnumbered}` 或 `# References {.unnumbered}`。
- 中文 `[@ref]` 前后不为排版硬加空格；英文保留正常词间空格。不要用连续空格、空行或制表符控制版面。
- ORCID 为可选字段；`equal-contributor: true` 表示同等贡献，`corresponding: true` 配合 `email` 指定通信作者。机构用 `affiliations` 的 `id` 与作者的 `ref` 关联。

## Word 中的摘要、题注与注

摘要在 YAML 的 `abstract` 中填写，模板排印同行标签。需要关键词时填写 `keywords: [词一, 词二]`。两份示例将关键词放在 `format.docx` 下，仅在 Word 首页显示。

图题写在图片方括号内，表题写在带 `#tbl-…` 的围栏中。表注使用 `.table-note` 放在对应表的围栏内，独立图注使用 `.figure-note` 紧接图片。题注在对象宽度内居中，注与对象左缘对齐。长表使用原生 Markdown 表头，Word 在续页自动重复列标题。带编号的公式按常规写作 `$$ … $$ {#eq-name}`，交叉引用使用 `@eq-name`。

## 样式与复现

`styles/` 保存参考文档、CSL 和来源清单；`_extensions/` 保存作者扩展及其矢量图标。它们是当前项目的本地副本，原模板更新不会自动改变已有项目。`styles/html/` 和 `styles/latex/` 是停用的历史样式，不参与当前渲染。

来源及 SHA-256 见 `styles/manifest.json`。更新样式或扩展前先保存项目版本，再检查实际输出。字体、Quarto、Pandoc、TeX 和 Word 版本也影响分页；完成的文档应同时归档源文件和最终 PDF。

Word 手工修改不会写回 QMD，下次渲染会覆盖生成文件。常规修改应在 QMD 或 Word 参考文档样式中完成。

## 可选：使用 Git

Quarto 默认不复制 `.gitignore` 和 `.gitattributes`；它们不是渲染依赖。如果新项目使用 Git，建议创建以下文件（已有文件时合并相应规则）。

`.gitignore`：

```gitignore
/output/
/.quarto/
/.qa/
*.tex
*.log
*.aux
*.out
*.toc
*.synctex.gz
!styles/latex/*.tex
!_extensions/**/latex-author-block.tex
```

`.gitattributes`：

```gitattributes
styles/** -text whitespace=cr-at-eol
_extensions/** -text whitespace=cr-at-eol
*.docx binary
*.png binary
*.pdf binary
```

前者排除生成文件并保留扩展所需的 LaTeX 源码，后者避免 Git 自动转换样式和扩展文件的换行符，保持快照散列一致。将 `styles/` 和 `_extensions/` 随项目提交即可。

## 从模板创建项目

在空目录中运行 `quarto use template <模板仓库或本地路径>`，按提示选择当前目录。`--no-prompt` 表示不询问确认，适合自动化脚本；日常使用可以省略。只有名为 `template.qmd` 的文件会自动按项目目录重命名，本模板的两份文件保留原名。

## 示例来源与许可

文献示例来自 Knuth 的 Literate Programming（DOI：10.1093/comjnl/27.2.97）和 Shannon 的 A Mathematical Theory of Communication（DOI：10.1002/j.1538-7305.1948.tb01338.x）。示例表格、曲线为合成数据。Word、CSL 和图标的来源及许可说明保留在样式与扩展目录中。
